<task type="auto">
  <name>Task 1: Generate uv.lock and verify dependency resolution</name>
  <files>uv.lock</files>
  <action>
Generate the lockfile covering all extras and dependency groups:

```bash
uv lock
```

uv 0.5+ automatically includes all extras and dependency-groups in the lockfile. No additional flags needed.

**If `uv lock` fails** with resolution errors:
- Check the error for which dependency/Python version caused the conflict
- If it is a pyramid or sqlalchemy pin issue with Python 3.12/3.13, try `uv lock --python 3.10` first to identify if the issue is version-specific
- If a dependency has no Python 3.10+ compatible release, that is a blocking issue — note it in the summary and stop

**After lock succeeds, verify:**

1. Lock contains test dependencies:
```bash
grep -c "pytest" uv.lock
```
Should be >0.

2. Lock contains doc dependencies:
```bash
grep -c "sphinx" uv.lock
```
Should be >0.

3. Lock passes freshness check:
```bash
uv lock --check
```
Must exit 0.

4. Sync the dev environment from the lock:
```bash
uv sync --group dev
```
This installs all dev dependencies from the locked versions. Must succeed.

**Commit the lockfile:**
```bash
git add uv.lock
git commit -m "chore(01-02): add uv.lock for reproducible builds"
```

<task type="auto">
  <name>Task 2: Build wheel, verify assets, and run full test suite</name>
  <files>(no files modified — build and verification only)</files>
  <action>
This task validates the entire Phase 1 migration end-to-end. All checks must pass.

**1. Build the wheel and sdist:**
```bash
uv build
```
This should produce files in `dist/`:
- `Kotti-2.1.0.dev0-py3-none-any.whl`
- `kotti-2.1.0.dev0.tar.gz`

**2. Inspect wheel for non-Python assets (PKG-05):**
```bash
# Count template files (.pt)
PT_COUNT=$(unzip -l dist/Kotti-*.whl | grep -c '\.pt$')
echo "Templates (.pt): $PT_COUNT"
test "$PT_COUNT" -gt 0 || { echo "FAIL: no .pt files in wheel"; exit 1; }

# Count locale files (.po and .mo)
PO_COUNT=$(unzip -l dist/Kotti-*.whl | grep -c '\.po$')
MO_COUNT=$(unzip -l dist/Kotti-*.whl | grep -c '\.mo$')
echo "Locale (.po): $PO_COUNT, (.mo): $MO_COUNT"
test "$PO_COUNT" -gt 0 || { echo "FAIL: no .po files in wheel"; exit 1; }

# Check for ZCML
ZCML_COUNT=$(unzip -l dist/Kotti-*.whl | grep -c '\.zcml$')
echo "ZCML: $ZCML_COUNT"
test "$ZCML_COUNT" -gt 0 || { echo "FAIL: no .zcml files in wheel"; exit 1; }

# Check for alembic directory
ALEMBIC_COUNT=$(unzip -l dist/Kotti-*.whl | grep -c 'alembic/')
echo "Alembic entries: $ALEMBIC_COUNT"
test "$ALEMBIC_COUNT" -gt 0 || { echo "FAIL: no alembic/ in wheel"; exit 1; }

echo "All wheel asset checks passed"
```

**3. Install from wheel in a fresh venv and verify no import errors:**
```bash
TMPDIR=$(mktemp -d)
uv venv "$TMPDIR/venv"
uv pip install --python "$TMPDIR/venv/bin/python" dist/Kotti-*.whl
"$TMPDIR/venv/bin/python" -c "import kotti; print(f'Import OK: {kotti.__file__}')"
rm -rf "$TMPDIR"
```
This validates the real-world install experience. If `import kotti` fails here, it means assets are missing or the wheel structure is wrong.

**4. Run the full test suite:**
```bash
uv run pytest --cov=kotti --cov-report=term-missing 2>&1 | tail -30
```
Capture the exit code. If tests pass, Phase 1 is complete. If tests fail:
- Failures related to path issues, import errors, or missing assets = Phase 1 bugs, fix them
- Failures related to pre-existing issues (unrelated to packaging) = note in summary, do not block

**5. Clean up build artifacts:**
```bash
rm -rf dist/ build/ *.egg-info src/*.egg-info
```
Build artifacts should not be committed.

Add `dist/`, `build/`, `*.egg-info` to .gitignore if not already present.
